# Запуск простейшего динамического инвентори, формирующего информацию о хостах программным образом


Создайте отдельный каталог, например hello и зайдите в него.

Скопируйте сюда файл hello.py из подкаталога hello материалов занятия.

Последовательно выполните:

```
./hello.py --host hello
./hello.py --host world
./hello.py --list
```

По каждому из хостов (hello и world) сначала по отдельности, затем вместе должна выдаться информация, в т.ч. их имена, ip(127.0.0.1), ansible_connection(local) в формате json.

Т.е. виден чистый результат работы программы hello.py


Затем последовательно выполните:

```
> ansible-inventory -i hello.py --host hello
> ansible-inventory -i hello.py --host world
> ansible-inventory -i hello.py --list
```

В формате json должны выдаться по сути те же результаты работы программы hello.py, но формально просканнированные и обработанные ansible-inventory


Последовательно выполните те же комнды еще раз, но с добавлением ключа -y:

```
> ansible-inventory -i hello.py --host hello -y
> ansible-inventory -i hello.py --host world -y
> ansible-inventory -i hello.py --list -y
```

Теперь те же резудьтаты должны выдаться в yaml-формате.


Выполните:

```
> ansible -i hello.py -m ping all
```

Должны пинговаться хосты (hello и world).


Создайте в каталоге hello файл ansible.cfg, содержащий строчки:

```
[defaults]
inventory = ../hello/hello.py
```


Повторите команду без -i hello.py:

```
> ansible -m ping all
```


Результаты не должны измениться.


Мы настроили и проверили работоспособность простейшего динамического инвентори, формирующего информацию о хостах программным образом.


# Корректировка манифестов терраформ


Создайте отдельный каталог, например tfs и зайдите в него.

Также желательно создать отдельный временный каталог в вашем облаке.

Скопируйте сюда манифесты терраформ (с учетом корректировки на предыдущем ДЗ), укажите идентификатор отдельного временного каталога в файле wp.auto.tfvars, проинициализируйте терраформ.


Пометьте виртуальные машины так, чтобы далее они могли автоматичеки определяться как члены группы wp_app в динамическом инвентори и плагине Ansible.Для этого в каждый ресурс описания виртуальных машин (в файле wp-app.tf) добавьте подблок:

```
  labels = {
    group = "wp_app"
  } 
```


и примените изменения в отдельном временном каталоге вашего облака.


# Настройка и проверка работы динамического инвентори, извлекающего инвормацию о хостах из файла состояния терраформа


В каталог tfs скопируйте ansible.cfg (из предыдущего ДЗ) и добавьте (или измените) строчки в разделе \[defaults\]:

```
inventory = ../tfs/tfs2inv.py
```

Сюда же скопируйте файл tfs2inv.py из подкаталога tfs материалов занятия.


Выполните:

```
> ansible-inventory --list
```

Должны выдаться правильные имена ВМ, их ip, а так же принадлежность к группе wp_app.


Выполните:

```
> ansible -m ping wp_app
```

Должны пинговаться ВМ группы wp_app.


Мы настроили и проверили работоспособность динамического инвентори, извлекающего инвормацию о хостах из файла состояния терраформа.


# Настройка и проверка работы плагина, извлекающего информацию о хостах из облака YC


Создайте отдельный каталог, например plugin и зайдите в него.

Скопируйте сюда ansible.cfg (из предыдущего ДЗ) и добавьте (или измените) в разделе \[defaults\]:

```
inventory = ./inventory

inventory_plugins = ./plugins/inventory
```

в раздел \[inventory\]:

```
enable_plugins = host_list,script,auto,yaml,ini,toml,yacloud_compute
```

Создайте соответствующие подкаталоги и поместите в ./inventory файл yacloud_compute.yml, содержащий:

```
plugin: yacloud_compute

yacloud_token: "<ваш OAuth-токен>"
yacloud_clouds:
- <имя вашего облака>
yacloud_folders:
- <имя каталога с помеченными виртуальными машинами>
yacloud_group_label: group
```


**Внимание: не допускайте утечки вашего OAuth-токен например через публичный git или иным образом!!!** Если считаете или подозреваете, что утечка все же произошла, немедленно отзовоите ваш OAuth-токен и получите новый согласно инструкции: <https://yandex.cloud/ru/docs/iam/operations/compromised-credentials#oauth-reissue>


В подкаталог ./plugins/inventory скопируйте файл yacloud_compute.py, находящийся по адресу <https://github.com/rodion-goritskov/yacloud_compute/blob/master/>


**Примечание**. Вместо OAuth-токена можно использовать временный IAM-токен (см. например https://yandex.cloud/ru/docs/iam/operations/iam-token/create#exchange-token), передаваемый через переменную среды (это безопасней), но тогда нужно использовать модифицированную версию плагина (файл yacloud_compute.py), которая находится в подкаталоге plugin/plugins/inventory материалов занятия. При этом в переменной среды YC_TOKEN должен содержаться IAM-токен для доступа в ваше облако, а в ./inventory файл yacloud_compute.yml, вместо строчки:

```
yacloud_token: "<ваш OAuth-токен>"
```

должна быть строчка:

```
yacloud_iam_token: "$YC_TOKEN"
```


Выполните:

```
> ansible-inventory --list
```

Должны выдаться правильные имена ВМ, их ip, а так же принадлежность к группе wp_app.


Выполните:

```
> ansible -m ping wp_app
```

Должны пинговаться ВМ группы wp_app.


Мы настроили и проверили работоспособность плагина, извлекающего информацию о хостах из облака YC.

Убедившись что все успешно работает, удалите инфраструктуру, созданную на шаге "Корректировка манифестов терраформ" (с целью экономии средств на вашем облачном эккаунте это лучше сделать сразу по завершении проверки и сохранения полученных манифестов, файлов настройки и логов запуска ансибла). После этого можете так же удалить отдельный временный каталог в вашем облаке (убедитесь, что он пустой).
